# Heuristics in Search

## 1. Satisficing Search

A satisficing search looks for a solution that is good enough rather than spending extra time trying to find the best possible solution.

In some real-world problems, finding an acceptable solution quickly is more useful than finding the mathematically optimal solution.

For example, a navigation system may choose a route that is reasonably short and can be found quickly instead of spending a long time searching for the absolute shortest route.

### Applications
- Real-time navigation
- Robotics
- Game AI
- Scheduling and planning problems


## 2. Admissible Heuristic

A heuristic is called **admissible** if it never overestimates the actual cost of reaching the goal.

The condition is:

**h(n) ≤ h*(n)**

where:
- **h(n)** = estimated cost from node n to the goal
- **h*(n)** = actual minimum cost from node n to the goal

An admissible heuristic is important in algorithms such as A* because, under the usual conditions, it allows A* to find an optimal solution.

### Example

Suppose the actual shortest distance from a city to the destination is 100 km.

If our heuristic estimates:
- 70 km → admissible
- 90 km → admissible
- 100 km → admissible
- 120 km → not admissible

The heuristic should never give a value greater than the actual remaining cost.


## 3. How to Formulate a Heuristic for a Search Problem

A heuristic can be formulated by finding an estimate of the remaining cost between the current state and the goal state.

A common approach is to simplify the original problem and calculate the cost of solving the simplified version.

The general steps are:

1. Clearly define the current state and the goal state.
2. Identify what makes the actual problem difficult.
3. Simplify or relax some of the restrictions of the original problem.
4. Estimate the cost of reaching the goal in this simplified problem.
5. Use that estimated cost as the heuristic value.
6. Check whether the heuristic is admissible if optimality is required.

### Example

For a pathfinding problem on a grid, the Manhattan distance can be used when movement is restricted to horizontal and vertical directions.

The Manhattan distance between two cells can be calculated as:

**h(n) = |x₁ - x₂| + |y₁ - y₂|**

This gives an estimate of how many grid moves are needed to reach the goal.


## 4. Generating Heuristics from Subproblems

A heuristic can also be generated by solving a simpler version of the original problem, called a **subproblem** or relaxed problem.

The restrictions that make the original problem difficult are temporarily removed or reduced. The cost of solving this simpler problem can then be used as a heuristic for the original problem.

### Example

Consider the 8-puzzle problem.

The original problem requires moving tiles while following the puzzle's movement restrictions.

Two commonly used heuristics are:

- **Misplaced tiles:** Count how many tiles are not in their goal positions.
- **Manhattan distance:** Add the number of horizontal and vertical moves required to place each tile in its correct position.

The simplified problem is easier to solve, so its solution cost provides an estimate for the original problem.

### Why This Works

If the simplified problem removes some restrictions from the original problem, solving it cannot require more cost than solving the original problem.

Therefore, the solution cost of the relaxed problem can provide an admissible heuristic when the relaxation is constructed appropriately.
